이 실수가 다시 반복되지 않도록 CLAUDE.md에 규칙을 추가합니다.

**등록할 내용:** $ARGUMENTS

---

## 진행 순서

### Step 1 — CLAUDE.md 읽기

현재 디렉토리의 `CLAUDE.md` 파일을 읽습니다.
없으면 `.claude/` 또는 상위 디렉토리에서 찾습니다.

### Step 2 — 규칙 분류

입력받은 내용을 분석하여 어떤 종류의 규칙인지 판단합니다:

| 종류 | 해당하는 경우 | 등록 위치 |
|------|-------------|----------|
| **MUST** | 반드시 해야 하는 패턴 발견 | `반드시 지켜야 할 규칙` 섹션 |
| **NEVER** | 절대 하면 안 되는 것 발견 | `절대 하면 안 되는 것` 섹션 |
| **학습된 규칙** | 프로젝트 특화 규칙 | `학습된 규칙` 섹션 |

### Step 3 — 규칙 작성

규칙을 간결하고 명확하게 작성합니다:

**좋은 규칙 예시:**
```markdown
- Entity 클래스에 비즈니스 로직(계산, 검증) 추가 금지
  - 이유: 도메인 로직이 분산되어 테스트가 어려워짐
  - 대안: Service 레이어에 로직 배치

- 새 API 엔드포인트 추가 시 반드시 SpringDoc 어노테이션 포함
  - 이유: API 문서 자동 생성 필요
```

**나쁜 규칙 예시:**
```markdown
- 코드를 잘 작성할 것  ← 너무 모호
- 항상 주석을 달 것   ← 실행 불가능한 규칙
```

### Step 4 — CLAUDE.md 업데이트

`학습된 규칙 (AI 실수 후 추가)` 섹션에 다음 형식으로 추가합니다:

```markdown
### YYYY-MM-DD — [실수 유형 한 줄 요약]
- **문제**: 어떤 실수가 발생했는가
- **규칙**: 앞으로 어떻게 해야 하는가
- **이유**: 왜 이 규칙이 필요한가
```

### Step 5 — 확인

업데이트한 내용을 보여주고 추가로 보완할 사항이 있는지 확인합니다.

## 이 커맨드를 언제 쓰나요?

- Claude가 CLAUDE.md 규칙을 어겼을 때
- 코드 리뷰에서 반복적인 지적사항을 발견했을 때
- 새로운 금지 패턴을 프로젝트 팀이 결정했을 때
- `/review` 결과에서 Critical/Major 항목이 나왔을 때

> **마구는 실수할 때마다 더 정교해집니다.**
> AI가 실수한 직후가 규칙을 추가하기 가장 좋은 타이밍입니다.
