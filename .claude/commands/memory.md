프로젝트의 Second Brain(`memory/MEMORY.md`)을 관리합니다.

**명령:** $ARGUMENTS

---

## 진행 순서

### `$ARGUMENTS`가 없거나 `show`인 경우 — 전체 조회

`memory/MEMORY.md`를 읽어 내용을 그대로 출력합니다.
파일이 없으면: "아직 기록된 내용이 없습니다. `/memory add <내용>`으로 첫 번째 기억을 추가하세요."

---

### `add <내용>`인 경우 — 새 기억 추가

1. `memory/MEMORY.md`를 읽습니다 (없으면 새로 생성)
2. 입력 내용을 분석해 적절한 카테고리를 판단합니다:
   - **결정 (Decision)**: 기술 선택, 아키텍처 결정, 방향 변경
   - **규칙 (Rule)**: 코딩 컨벤션, 금지 패턴, 팀 규칙
   - **참고 (Reference)**: 외부 링크, 관련 파일 경로, API 문서
   - **교훈 (Lesson)**: 삽질 기록, 해결한 버그, 주의사항
3. 다음 형식으로 파일에 추가합니다:

```markdown
## YYYY-MM-DD: [한 줄 제목]

**카테고리:** 결정 | 규칙 | 참고 | 교훈

[내용 상세]

**관련 파일:** (있으면)
```

4. 추가한 내용을 보여주고 확인합니다.

---

### `search <키워드>`인 경우 — 검색

`memory/MEMORY.md`에서 키워드가 포함된 항목을 찾아 관련 섹션을 출력합니다.
없으면: "관련 기억을 찾을 수 없습니다."

---

## 사용 예시

```
/memory                              # 전체 내용 보기
/memory add JWT에서 세션으로 변경     # 새 기억 추가
/memory search 인증                  # "인증" 키워드 검색
```

---

> **언제 쓰나요?**
> - 중요한 기술 결정을 내렸을 때
> - 같은 실수를 두 번 하고 싶지 않을 때
> - 나중에 "왜 이렇게 했지?"가 생길 것 같을 때
> - `CLAUDE.md`는 규칙, `memory/`는 맥락과 히스토리
