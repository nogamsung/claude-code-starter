프로젝트의 Second Brain(`memory/MEMORY.md`)을 관리합니다.

**명령:** $ARGUMENTS

---

## 진행 순서

### `$ARGUMENTS`가 없거나 `show`인 경우 — 전체 조회

`memory/MEMORY.md`를 읽어 내용을 그대로 출력합니다.
파일이 없으면: "아직 기록된 내용이 없습니다. `/memory add <내용>`으로 첫 번째 기억을 추가하세요."

---

### `add <내용>`인 경우 — 새 기억 추가

1. `memory/MEMORY.md`를 읽습니다 (없으면 새로 생성)
2. 입력 내용을 분석해 적절한 카테고리를 판단합니다:
   - **결정 (Decision)**: 기술 선택, 아키텍처 결정, 방향 변경
   - **규칙 (Rule)**: 코딩 컨벤션, 금지 패턴, 팀 규칙
   - **참고 (Reference)**: 외부 링크, 관련 파일 경로, API 문서
   - **교훈 (Lesson)**: 삽질 기록, 해결한 버그, 주의사항
3. 다음 형식으로 파일 끝에 추가합니다:

```markdown
## YYYY-MM-DD: [한 줄 제목]

**카테고리:** 결정 | 규칙 | 참고 | 교훈

[내용 상세]

**관련 파일:** (있으면)
```

4. 추가한 내용을 보여주고 확인합니다.

---

### `search <키워드>`인 경우 — 검색

`memory/MEMORY.md`에서 키워드가 포함된 항목을 찾아 관련 섹션을 출력합니다.
없으면: "관련 기억을 찾을 수 없습니다."

---

## 자동 기록 트리거 (사용자가 요청하지 않아도 기록)

아래 상황이 발생하면 **대화 흐름 중에 자동으로** `memory/MEMORY.md`를 업데이트합니다.
사용자에게 별도로 확인을 요청하지 않고 기록 후 "memory에 저장했습니다." 한 줄만 언급합니다.

| 트리거 | 기록할 내용 |
|--------|------------|
| `/plan` 승인 후 구현 시작 | 구현할 기능, 선택한 설계 방식, 이유 |
| `/improve` 로 새 규칙 추가 | 어떤 실수였는지, 추가된 규칙 요약 |
| 복잡한 버그 해결 | 원인, 해결 방법, 재발 방지 포인트 |
| 외부 라이브러리/API 도입 결정 | 선택 이유, 대안으로 고려했던 것 |
| 아키텍처 또는 폴더 구조 변경 | 변경 전/후, 변경 이유 |
| 성능 문제 발견 및 해결 | 병목 지점, 해결 방법, 측정 결과 |

---

## 사용 예시

```
/memory                              # 전체 내용 보기
/memory add JWT에서 세션으로 변경     # 새 기억 수동 추가
/memory search 인증                  # "인증" 키워드 검색
```

---

> **언제 쓰나요?**
> - 중요한 기술 결정을 내렸을 때
> - 같은 실수를 두 번 하고 싶지 않을 때
> - 나중에 "왜 이렇게 했지?"가 생길 것 같을 때
>
> **구분:**
> - `memory/MEMORY.md` — 맥락과 히스토리 (왜 이 결정을 했는가)
> - `CLAUDE.md` — 규칙 (앞으로 어떻게 해야 하는가)
